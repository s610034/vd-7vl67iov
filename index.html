產生設定包

會產出:inventory.yml、group_vars/all.yml、site.yml(主 playbook,含自動產生憑證)、roles 內各角色 tasks、verify.yml(驗收腳本)、deploy.sh(一鍵執行入口)、README.md、SOP.md(自動化卡住時可接手的完整手動部署手冊)。全部打包成一個 zip。
📦 這包下載下來怎麼用
解壓縮後,在中央控制機(能 SSH 連到全部節點的那台,不是任何一台 Wazuh 節點本身)依序執行:
第 0 步(VM 靜態 IP)依你上面選的虛擬化平台,三種情況不一樣:
  • Proxmox VE / KVM——把 00-set-static-ip.sh 帶到 PVE 宿主機執行(不是中央控制機),用 qm guest exec 批量幫各 VM 寫入靜態 IP 與主機名稱。需要每台 VM 都已安裝 QEMU Guest Agent,不然這台會被跳過。
  • VMware vSphere——這個工具不儲存/不碰 vCenter 帳密,沒辦法自動執行,只能產生 00-vmware-customize-notes.md 給你參考:裡面是 govc 或 PowerCLI 的**指令範本**(不是可直接跑的腳本),要你自己填入 vCenter 帳密/VM 名稱後手動執行,把每台 VM 的 IP/Gateway/DNS 設好。執行完建議先 ping/ssh 確認每台新 IP 連得到,再往下走。
  • 其他平台 / VM 已有 IP——工具假設這些 VM 早就有正確的 IP 了(DHCP 保留或你已手動設好),完全不會產生額外的網路注入腳本。這種情況直接跳過第 0 步,從下面「裝 Ansible」開始做。
  1. 中央控制機裝 Ansible:sudo apt-get install -y ansible
  2. chmod +x deploy.sh
  3. ./deploy.sh check — 只測試 SSH 連線,不改任何東西,先確認全部節點連得到
  4. ./deploy.sh install — 執行完整部署(約 15–30 分鐘),背後會依序:自動產生並分發 TLS 憑證 → 全主機基礎環境設定(裝套件/關 swap)→ Indexer 叢集 → Manager 叢集 + Filebeat → Dashboard → LB(如有)→ NIDS(如有)
  5. ./deploy.sh verify — 部署完成後跑健康檢查(對應 verify.yml)
各檔案功能:
  • deploy.sh — 一鍵入口,上面 network/check/install/verify 四個指令都是呼叫這支
  • inventory.yml — 這次部署的主機清單(IP、規格),Ansible 靠這個知道要連哪些機器
  • group_vars/all.yml — 這次的密碼、叢集金鑰、VIP/DNS/Gateway 等變數
  • site.yml — 主要部署邏輯(deploy.sh install 實際執行的內容)
  • verify.yml — 部署完成後的驗收檢查(deploy.sh verify 執行的內容)
  • roles/ — 各角色(common/certs_bootstrap/indexer/manager/dashboard/loadbalancer/nids)實際安裝步驟的來源,想知道某個環節具體做了什麼可以直接打開看
  • certs/ — TLS 憑證存放處,執行 site.yml 時自動產生,不用自己放
  • README.md — 完整文字版使用說明(跟這裡的內容大致對應)
  • HARDWARE_SPEC.md — 這次填寫的硬體規格總表,方便跟客戶對規格
  • SOP.md — 自動化中途卡住/失敗時,可以直接接手做完的完整手動指令清單

把系統遷移到客戶正式網段 選用,通用參考文件

這是獨立於上面部署包之外的另一份文件:如果你先在測試網段(例如公司內部)把整套系統建好、驗證過,之後才要正式搬到客戶現場的網段,裡面有完整步驟,包含最重要的一條鐵律——批次切換腳本刻意排除 PVE 宿主機自己,宿主機 IP 只能在現場、接實體螢幕鍵盤時才手動改,避免遠端操作把自己唯一的管理通道切斷。內容是通用範例(不會帶入你上面填的實際主機資料),下載後把裡面的範例 IP 換成你的實際規劃即可。
